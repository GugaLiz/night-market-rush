## 1. 目标、范围与决策

将当前 TypeScript + 浏览器 Canvas 2D + HTML/CSS 的游戏，完整迁移到一个 Cocos Creator 工程；由该工程分别构建 Web、微信小游戏和 Windows 桌面版。保持游戏既有玩法、内容、风格、操作和用户设置。复用经验证的平台无关规则，不把“全部迁到 Cocos”理解成必须重写已经正确的规则；最终运行入口、表现层和平台接入统一由 Cocos 工程承载。

**版本决策：**Web 开发工程现使用官方 Cocos Creator 3.8.8；该版本的微信和 Windows 构建、工具链及设备兼容性仍需实际验证。API、编辑器和官方文档必须与实际版本匹配。不能把 npm 包版本当引擎版本，也不混用不同大版本的示例。

**范围：**正式游戏、试玩专用内容、图鉴、设置、现有数据保护、构建及部署流程都纳入；登录、广告、排行、付费和跨平台云存档不作为本次新增功能。微信正式发布所需账号、资质和备案单独核验，技术构建成功不等于获准上线。

**工作方式：**先保留可运行旧版与可恢复基线，分阶段双版本对照；完成全部验收和切换后，再按已核对清单清理旧运行实现。过程中不得把临时双版本当成最终架构，也不得因方便直接删除未迁移内容或测试。线上发布和清理遵循当时用户指令及项目发布流程。

## 4. 目标架构与约束

1. **单一规则源：**迁入 `core` 与 `shared` 的可复用 TypeScript；保持数据、事件、碰撞、随机、命中、帧顺序和配置职责。仅在确有需要时修改并以差异测试证明行为。
2. **Cocos 表现：**Cocos 场景、节点、组件、相机、图集/精灵、动画及必要材质消费游戏状态与事件；引擎 Canvas/UI 节点不是浏览器 Canvas。视觉插值不得改变权威模拟状态。
3. **平台服务：**定义输入、屏幕与安全区、生命周期、存储、音频、触觉、资源和诊断边界。保持各平台能力可查询、失败可处理；不得在核心规则中散落微信或浏览器 API。
4. **时间与中断：**保留 1/60 秒规则步长、累积与暂停语义，避免另启计时器改变规则；后台/失焦/切场景清理输入，不做后台补算。组件启停与应用前后台是不同事件，各自清理监听、计时器和异步回调。
5. **资产及数据：**在编辑器中正确导入与管理 `.meta`、UUID、场景及预制体引用；场景/资源的加载和释放必须有明确所有权。检查图集、纹理、字体、音频格式在每个平台的兼容性，不依赖文件扩展名猜测实际支持。
6. **性能：**批次、纹理、材质、层级、遮罩、动态文字与对象复用根据真实分析结果优化；不预先假设每个敌人一个节点或某种批处理一定可行。

## 6. 存档、迁移及回滚

- 当前 Web 主键是 `night-market-rush.save.v4`，旧键为 `night-market-rush.save.v1`；当前数据 schema 为 `version: 1`，规则版本为 `night-market-4.0`，见 `src/platform/storage.ts` 与 `src/shared/types.ts`。
- 旧键现行逻辑仅读取设置和教程状态，不迁入旧规则的时间最高分；新方案须保持这一行为。主键需要保留损坏数据备份、未知更高 schema 不覆盖、旧规则最高分隔离、设置修复备份、同规则多标签最高分合并及写入失败时仅会话生效。
- 新 Web 版先验证同源、同协议、域名和端口下实际可读旧键，再验证首次迁移、重复启动、写入失败、旧新标签同时打开和回退；不能假定 Cocos 存储封装使用相同位置。迁移前保留原始数据及回退步骤，不破坏未知版本。
- 微信和 Windows 的存储命名空间独立，默认不与网页或彼此同步。跨平台导入/云同步是额外需求，不以迁移为借口自动上传玩家数据。
- 回滚验收包括：不覆盖线上旧产物；还原旧 Web 部署；在真实迁移样本上验证旧版仍能读取已保留的数据。共享键写入与并发策略须事先完成设计并测试。

| Windows | 完整分发目录在代表性机器启动、窗口与 DPI、键鼠、失焦、音频、存档、重新启动和缺失依赖提示 |

每端至少覆盖：首次加载、完整一局、图鉴、设置、暂停恢复、死亡复活、结算、精英及首领、高密度技能战斗、退出重进、存档异常。训练在开发或试玩构建中验证；正式构建检查训练与测试入口不存在。重力、触觉、离线和设备特性按目标实际支持单列。

性能目标在阶段 0 用代表性设备与用户确认的目标确定；使用同设备、同场景、同采样时间比较 FPS、p95 帧时间、内存、首屏和包体。报告采样方法、设备、温度或省电状态等影响因素；不得拿模拟器或历史记录代替本次真机结果。

**记录模板：**日期 | 旧版/新版提交 | 引擎及工具版本 | 构建配置 | 平台与设备 | 场景和操作 | 预期 | 实测及证据链接 | 通过/失败/受阻 | 缺陷与后续。

## 8. 发布、依赖和风险

- **Web：**保留可用线上地址与 Pages 子路径，检查资源相对路径、缓存更新、静态服务、manifest 与图标。预发布验证后才切换现网，预先验证回滚。
- **微信：**需要开发者工具、适用 AppID、测试授权及 Android/iPhone 真机；包体、分包、域名、资源分发、备案、内容及出版要求以当时官方平台和主管部门规则为准。技术试玩、体验版、审核和正式发布分开记录。
- **Windows：**需要 Windows 和与目标 Creator 版本匹配的 Visual Studio/C++ 工具；验证完整程序及依赖，安装包、签名或商店要求取决于实际分发方式。
- **主要风险：**复杂画面无法一比一复用；音频合成需重制；密集怪和特效导致性能回退；旧数据丢失；UI 可访问性下降；三端输入或生命周期差异；构建包增长；线上自动部署误触发；审核材料不足。每项须在台账中标明责任、验证及处置。
