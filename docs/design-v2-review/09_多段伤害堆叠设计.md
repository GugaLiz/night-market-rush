# 多段伤害与多行堆叠反馈

用户希望同一怪物在多次命中、不同武器或多段攻击后看到多行掉血。本页覆盖 08 中“同怪在 0.12 秒内统一合成一个数字”的显示方案；生命值、伤害计算和受击保护继续按 08 执行。

## 1. 总血量与本次伤害分开

采用 **一条总血量条＋最多三行伤害记录条**。总血量条只表示该怪物还剩多少 HP；每次真实扣血对应一行“来源小图标＋数字”，轻微半透明底用于对比，不重复绘制红色生命填充。既满足多行掉血反馈，也避免玩家误以为怪物有三条命。

玩家打怪继续使用米白/浅金数字，例如 24、12；玩家自己的受伤使用独立红色 -12。颜色只是辅助，伤害归属同时由图标、锚点、位置和正负号识别。分数仍单独结算，不插入这组三行。

## 2. 连续命中的排入与退出

| 规则 | 候选表现 |
|---|---|
| 一次真实命中 | 即时排入新一行；去重使用攻击实例与合法命中事件，不按动画帧重复创建 |
| 行的顺序 | 旧在上、新在下；最新行最靠近怪物血条，亮度略高 |
| 每行寿命 | 约 1.2 秒，按自身命中时刻计时；旧行逐渐淡出，不被新命中无限续命 |
| 行距 | 初拟 20–24 逻辑单位，适配后以手机可读性为准；堆叠组不能挡脸和脚点 |
| 排入动画 | 约 0.08–0.12 秒平滑让位，最新数字轻微强调；不随机四处抛飞 |
| 同武器多段 | 只要是合法的不同伤害事件就分别显示，例如餐盘去程 22、回程 18 |
| 多来源叠加 | 用图标区分，例如快刀 24、滑板 12、滑板 12；不把它们直接吞成 48 |
| 同刻事件 | 按逻辑事件时间、稳定编号排序，不依赖帧率或音效播放先后 |

第四次有效命中到来时，最新两击继续分别显示，较早且未过期的事件折叠到第一行，例如“较早 36 · 2击”。同来源可保留小图标，多来源则用中性的叠层标记，不能错误地归为某一把武器的伤害。该行记录的成员仍各自到期，合计只包含未过期成员，不成为整局累计伤害。

折叠只影响显示，不改真实扣血。已经结束的旧事件不得重新出现；怪物死亡后停止追加，最后一组最多保留约 0.4 秒并随退场淡出。过量伤害按实际扣除显示，不能因为数值看起来更大就多报。

## 3. 多只怪同时掉血时怎样避让

- 每组固定关联一只怪物的稳定身份，从其头顶上方开始排，必要时整体移动到侧上方。不能把一组拆散到邻怪头上。
- 优先避开玩家脸、脚点、敌方冲刺预警、顶部 HUD 与摇杆；血条始终留在怪物附近，伤害组允许小范围错开。偏移过大时使用短而轻的连接提示，仍挡路则少显示远处组，不拉长线跨半屏。
- 多组相交时整体做轻微横向错位，并保留约 0.20 秒布局稳定窗口，避免每帧左右乱跳。最新锁定目标不应把已经出现的邻近数字骤然顶飞。
- 全屏最多 **12 行敌人伤害记录**，折叠行也占一行；另外预留玩家受伤一行、恢复一行。优先给锁定目标和近身威胁保留三行，再分配其他怪物。
- 超预算的远处命中仍真实扣血、更新血条并保留局部命中光效；新数字可不显示，不建立稍后集中喷出的长队列。统计记录仍保留实际事件，视觉省略不改变数据。
- 普通怪受伤短显血条；当前锁定目标或试验场可附具体 HP 数字。设计图为了审核计算，会明确标出两只示例怪物的剩余数值。

## 4. 设计图所示的两个例子

| 目标 | 多行顺序（旧→新） | 结果 |
|---|---|---|
| 大碗面怪 | 快刀 24 → 滑板 12 → 滑板 12 | 120 − 24 − 12 − 12 = **72 HP**，总条为 60% |
| 外卖盒怪 | 餐盘去程 22 → 餐盘回程 18 | 60 − 22 − 18 = **20 HP**，总条为约 33% |

角色当前手持拆箱快刀、滑板技能生效，餐盘是换装前已经投出且尚未回收的实体，符合旧投射物继续完成的规则；不代表同时装备两把主武器。图中玩家仍是 76/100，红色 -12 是玩家自己的独立受击事件，不属于怪物掉血组。

示例中的三个伤害不是同一帧伪造的三次扣血，而是短时间内先后发生、当前仍在可见寿命中的事件。显示多行不改变滑板每敌 0.5 秒的伤害间隔。

## 5. 减少动态与实际验证

减少动态模式仍保留三行、来源和真实数值，只取消弹跳与缩放，使用固定位置排入和淡出。低画质可省底纹和装饰火花，不能先省玩家受伤数字或真实 HP。

确认开发后，至少检查：三次慢速命中能看清先后；同刻两个来源不互相覆盖；第四击正确折叠；持续攻击不会让旧合计无限增长；一个怪死亡不把标签转移给复用编号的新怪；60 怪场景下总预算可控；最窄手机横屏不遮挡移动与预警。

当前交付为战斗设计图及规则说明，最终行距、字重、显示寿命和动态节奏仍需实机试玩，不从静态图判断动画已合格。
