# 平台接入与当前完成边界

当前交付使用 TypeScript 游戏模拟 + Canvas 2D 战场 + Web 页面界面。网页可直接运行；本轮没有编译 Android / iOS 安装包，也没有提交微信小游戏。原先文档中的 Cocos 是候选方案，本次先落地可独立部署的 Web 架构，并保留可复用的核心规则和数据契约。

## 已实现

- `src/core`：不调用 DOM、浏览器存储、音频、网络或平台 SDK 的游戏规则。
- `src/platform/storage.ts`：本地存档校验、损坏备份、规则版本隔离、未来版本保护、设置和最高分；不可写时只在会话中生效并返回失败状态。
- `src/platform/input.ts`：键盘、浮动触控摇杆、设备方向权限与校准、死区和平滑、丢失焦点清输入。输入输出统一为二维方向/力度。
- `src/platform/audio.ts`：原创程序合成音效和可循环音乐，独立音乐/音效音量、总静音、命中聚合和限声部、暂停时停止待播放声音。
- `src/platform/contracts.ts`：宿主能力与服务的明确边界。这里只定义契约，不以接口存在宣称某平台已接入。

## Android / iOS 接入路线

可用 Capacitor 容器加载本项目静态构建，通过原生插件补充设备运动、音频中断、退出和安全区能力。保留相同核心逻辑、资源与存档版本；原生插件不直接更改分数和技能规则。Android 需要 SDK/签名和真机测试；iOS 需要 Mac、Xcode、签名和真机测试。

若未来迁到 Cocos 或其他原生引擎，可以复用纯 TypeScript 的模拟和配置，重新实现输入/表现/UI，不能把 Web DOM 直接当原生场景。需要建立对应平台的性能和生命周期回归，不能保证仅换打包目标即可完成。

## 微信小游戏接入路线

微信小游戏不是完整浏览器；当前 DOM 弹层、页面 CSS 和浏览器音频不能直接照搬。应以核心模型为依据新增以下实现：

| 能力 | 需要替换的部分 |
|---|---|
| 画布与图片 | `wx.createCanvas` / 资源加载与运行时可用的绘制上下文 |
| 游戏内 UI | 用 Canvas UI 或引擎组件实现同样的状态流程；不使用 document 挂载 |
| 输入 | 微信触摸和设备运动 API，映射相同 Vec；暂停/恢复清输入 |
| 存档 | `wx` 本地存储，保留 SaveData 与规则版本保护 |
| 音频 | 平台音频对象/缓冲播放；可将当前原创合成声音烘焙为资源，需实测延迟和并发 |
| 生命周期 | hide/show、安全区、胶囊避让、资源缓存和失败重试 |

任何平台接入后，先检查固定战场视野、同帧拾取优先顺序、无后台补算和记录保护，再宣称支持。未来备用模式通过主题资源映射进入，不复制三份规则实现。

## 输入与音频细节

摇杆回调 x/y 是相对画布容器左上角的 CSS 像素，dx/dy 是可见柄偏移；游戏意图来自 `getVector`，不使用 CSS 像素改变角色速度。移动热区按左右手设置选半屏，按钮与弹层不接收游戏移动。

重力模式需要浏览器支持及可能的用户授权。`requestTilt` 等待首个有效采样，`calibrate` 只保存当前会话中立姿势。显示方向改变会暂停并要求重新校准。运行中连续无采样超过约 1.5 秒会通过暂停回调停止当前操作，避免沿旧姿势继续移动。各平台传感器坐标和声音延迟仍需真实手机测试。

音频在首次用户操作后解锁；浏览器拒绝时可以静音继续。音乐由原创五声音阶旋律、低音与噪声打击合成；电扇、滑板、汽水、预警、失败、拾取和纪录各有独立包络与声部。没有提取原作素材。程序合成适合本次 Web 完整玩法版本；后续可替换同名事件的专业录音而不改核心模拟。
